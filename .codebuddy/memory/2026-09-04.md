## 打包踩坑与结论

- pnpm 隔离链接：`libsql` 不是 server 的直接依赖，须先解析 `@libsql/client` 包根目录再解析 libsql；
  部分包的 exports 不暴露 ./package.json，需从主入口向上定位包根目录。
- 复制 junction：`fs.cpSync` 默认尝试创建符号链接（Windows 下需管理员权限 → EPERM），
  必须 `dereference: true` 展开为实体文件，产物才能拷贝到任意机器。
- Node 的 `Dirent.isDirectory()` 对 junction 返回 false（识别为符号链接），需同时判断 `isSymbolicLink()`。
- ESM 输出下 CJS 依赖的动态 `require('events')` 会抛错，必须注入 banner：
  `import { createRequire as __createRequire } from 'node:module'; const require = __createRequire(import.meta.url)`

## 新增：数据库每日备份（zip + 邮件外发 + 邮箱保留 20 份）

需求：每天定时把 study.db 打包成 zip 并以邮件发到指定邮箱（用户使用 QQ 邮箱自发自收）。
已确认的设计决策：
- 快照用 `PRAGMA wal_checkpoint(TRUNCATE)` + 文件复制（避免 SQL 拼接，符合既有约定）
- zip 不加密，安全边界依赖 SMTP TLS
- 配置缺失时告警并禁用备份，主服务照常启动（辅助功能不拖垮主服务）
- 保留按「邮件份数」而非天数；删除方式为移入「已删除」文件夹（可恢复）
- IMAP 凭据可留空，自动复用 SMTP 凭据
- 自发自收在「收件箱」与「已发送」各留一份副本，两个文件夹都需清理，各留 20 封

新增（5）：`server/src/services/mailer.ts`（SMTP + 超时 + 指数退避重试）、
`backup.ts`（快照/zip/调度判定/编排）、`backup-retention.ts`（IMAP 双文件夹清理）、
`__test__/backup.test.ts`、`__test__/backup-retention.test.ts`。
修改（6）：`db/index.ts` 导出 `DB_FILE_PATH`、`index.ts` 挂载 `setupDailyBackup()`、
`package.json`（nodemailer@9 / archiver@8 / imapflow@1.7）、`.env.example`、`README.md`、`pnpm-lock.yaml`。

技术要点（易踩坑）：
- 主题前缀必须用纯 ASCII `[StudyPlus Backup]`：中文前缀经 SMTP 会被 MIME 编码为 `=?UTF-8?B?…?=`，
  IMAP 侧取回的 subject 无法按前缀匹配，二次校验会恒定失效。
- archiver 8 是 ESM 且无默认导出，须用 `import { ZipArchive } from 'archiver'`。
- imapflow 的 `specialUseHints` 属于 `ListOptions`（`list()` 的参数），不在 `ImapFlowOptions` 里。
- imapflow 的 `list()` 返回 `ListResponse[]`，不是 `MailboxObject[]`（后者含 uidValidity 等字段）。
- 测试替身暴露计数要用对象字面量的 getter，`Object.assign` 会求值 getter 并复制快照值。
- 防误删三重防护：自定义头精确命中 → 逐封校验主题前缀 → 单文件夹单次移动不超上限（默认 5）。
- 重试语义：`failed` 不写日期守卫（当天可重试），`skipped`（超限）会写入（重试无意义）。
