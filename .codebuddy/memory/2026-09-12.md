# 2026-09-12

## 修复 AI 评估 JSON 被截断导致的「Invalid evaluation response format」
- 现象：日志大量 `[DeepSeek Truncated] 检测到 max_tokens 截断` + `[AI JSON Parse Failed]`（Unterminated string，rawLength 377~1403）+ `AI evaluation error: Invalid evaluation response format`，前端最终只看到「评估出错，请稍后重试」。
- 根因 1：`server/src/services/ai/core.ts` 的 `callDeepSeek` 只在 `!content`（内容为空）时才处理 `finish_reason === 'length'`。截断但仍返回部分文本（最常见情形）时，函数直接把残缺 JSON 交给调用方，`safeJsonParse` 必然失败，下游抛出「响应格式错误」，掩盖了真实的预算不足问题，日志里也只留下误导性报错。
- 根因 2：`server/src/services/ai/studynotes.ts` 中评估/预习分析的 `max_tokens: 2000` 偏小，deepseek-v4-flash 的推理 token 计入该预算，留给 JSON 输出的余量很小，因此常在中途截断。
- 改动（2 个文件）：`core.ts` 新增 `MAX_TOKENS_CEILING=32000`、`DEFAULT_MAX_TOKENS=8000` 与 `growMaxTokens()`；JSON 模式（`response_format: json_object`）下「截断」与「空响应」统一纳入重试，按 1.5 倍扩容 max_tokens；已无扩容空间或重试耗尽时抛出明确错误，绝不返回残缺 JSON；纯文本调用维持原语义（仍允许返回截断内容）。同时补齐该文件缺失的头部模块文档注释。
- 改动（同批）：`studynotes.ts` 的 `evaluateStudynotesReflection`、`analyzePreview` 由 `max_tokens: 2000` 提升至 `6000`。
- 验证：server `tsc --noEmit` 通过、无 lint 报错；`vitest run studynotes preview-quiz` 7/7 通过（studynotes 2 + preview-quiz 5）。
- 环境备忘：vitest 5 已移除 `--reporter=basic`；PowerShell 下 `pnpm --filter server exec vitest run` 会被判定为 watch 命令而吞掉输出，改用 `*>` 重定向到文件后再读取。
