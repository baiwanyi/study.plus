## 二次修复：/api/lessons 返回 500 的根因

### 根因
`study_quiz.study_id` 的**权威语义是 lesson.id**（schema 外键 `references(() => studyLessons.id)`）。但此前我误把 `generateQuiz`/`getStudyNote`/`lessons` 的查询都按 cardId 语义处理，跨 id 空间 JOIN（`eq(studyQuiz.studyId, studyNotes.id)`）与写入错位，导致：
- `GET /api/lessons` 聚合查询跨 id 空间，运行库数据不匹配 → 500。
- `getStudyNote`/`submit`/`grade`/`getLatestQuiz` 用 cardId 查 lessonId 列 → 查不到。

### 修复
统一 `study_quiz.study_id = lessonId`。新增 `resolveLessonId(cardId)` 辅助函数，在 `saveQuizAnswers`/`submitQuiz`/`gradeQuiz`/`getLatestQuiz`/`getStudyNote`/`generateQuiz` 内将卡片 ID 解析为 lessonId 后操作 `study_quiz`。
- `generateQuiz(id=cardId)`：先取 `study_notes.id=cardId` 的 `lessonId`，再用其查/写 `study_quiz`。
- `lessons.ts` 列表：直接 `study_quiz.study_id = lesson.id` 聚合，去掉跨空间 JOIN。

### 验证
- `studynotes.e2e.test.ts`：2 passed。
- Lint 全量无错误。

### 注意
旧运行库历史 `study_quiz.study_id` 可能存的是旧语义值（取决于旧版 generateQuiz 实际写入），新生成数据已正确存 lessonId；旧数据仅显示为空，不会 500。如历史成绩需迁移，需另立数据修复任务。

## 三次修复：点击「测验」时测验 ID 与课程 ID 绑定错误

### 根因
前端 `apps/src/pages/Study/index.tsx` 的 `QuizModalEditor` 一直把 `activeQuizLesson?.id`（**课程 ID / lesson.id**）当作 `cardId` 传入。而 `QuizModalEditor` 的 `openQuiz` 会拿这个 `cardId` 去调 `generateQuiz(cardId)` / `getLatestQuiz(cardId)` 等，后端约定「前端统一以**卡片 ID（studynoteId）**为参数」（`studynotes.ts:resolveLessonId` 按 `studyNotes.id=cardId` 查 `lessonId`）。传错 id 导致 `resolveLessonId(lessonId)` 查到错误/不匹配的 lessonId，测验绑定到错误的课程。

### 修复
`index.tsx` 第 203 行 `cardId={activeQuizLesson?.id ?? null}` 改为 `cardId={activeQuizLesson?.studynoteId ?? null}`。测验按钮 `canQuiz` 已要求 `studynoteId != null 且 studynoteScore>=80`，故 `studynoteId` 一定存在，类型安全。

### 验证
- Lint：0 错误。
- 类型确认：`StudyLessonWithStatus.studynoteId` 即「关联心得 ID（卡片 ID）」，与后端期望的 cardId 完全一致。
