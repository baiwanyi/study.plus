# 2026-11-18 工作记录

## 修改内容摘要

新增【看图说话】模块并按方案完成落地，包含两个子功能：

1. 图片采集：服务端接入 Unsplash 搜索与按 ID 采集，下载时经 imgix 参数固定长边 1600px，
   以 `<unsplashId>.jpg` 保存到数据库目录同级的 `unsplash/`，并以图片 ID 唯一键实现幂等；
   采集阶段由 AI 生成 5–8 个中文关键词，作为练习提示与评分依据。
2. 看图说话练习：前端提供图片展示、描述输入、字数限制、关键词折叠提示、四维 AI 评分结果
   与练习历史回看；评分维度为切题与完整性 30、观察细节 25、语言表达 25、关键词覆盖 20，
   AI 输出经 JSON 结构校验、分数钳制与合计一致性校验后才落库。

安全与工程约束同步落地：Unsplash Access Key 仅存服务端环境变量并加入模板；搜索接口独立限流、
评分复用 aiLimiter；图片只接收 ID、下载目标限定 Unsplash 官方域名防 SSRF；文件名白名单防目录穿越；
CSP 的 img-src 增加 images.unsplash.com 仅用于缩略图预览；响应均经 DTO 白名单构造。

验证：前后端 tsc 类型检查通过；`pnpm build` 构建成功；`pnpm db:migrate` 建表成功；
`pnpm test` 共 10 个测试文件、86 项测试全部通过（无新增失败）。

## 修复：部署环境 picture_images 查询失败

### 修改内容摘要

- 现象：部署环境添加图片时报 `Failed query: select ... from "picture_images" where "picture_images"."unsplash_id" = ? limit ?`，这是 Drizzle 外层包装错误，底层原因被错误处理吞掉。
- 原因：迁移脚本对 `picture_images` 的 `thumbnail_url`、`draft_content` 均提供了旧库补列分支，唯独 `keywords` 缺少对应 ALTER 分支；旧部署库表结构与当前 schema 不一致时即查询失败。
- 修复：`server/src/db/migrate.ts` 补齐 `ALTER TABLE picture_images ADD COLUMN keywords TEXT` 幂等迁移，并按规范补充首部 JSDoc；`server/src/routes/phototalk.ts` 在服务端日志中输出 Drizzle 底层 cause，便于后续定位真实错误。
