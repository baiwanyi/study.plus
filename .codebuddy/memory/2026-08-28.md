- 需求：无账号系统，孩子移动端新建答题、家长电脑端查看同一测验；要求家长端显示孩子端的倒计时且自身不倒计时；二次打开题目为只读，点【继续答题】才恢复计时与作答
- 根因：原 remainingSeconds 是「剩余量」快照且仅关闭弹窗时落库 → 作答中库里恒为满额 2700，且任何端读到的都是已过期量，各自 Date.now()+快照 起算 → N 端 N 个互不相干的 deadline
- 方案：数据语义从「剩余量」升级为「绝对截止时刻」。新增 study_quiz.deadline_at（Unix 毫秒）作多端唯一真源，前端一律不得自行创造 deadline
- 服务端：schema 加可空列 deadline_at；migrate 幂等 ALTER TABLE（存量不批量补算，作答端首次打开惰性裁决）；mapQuizRow 映射；新增 startQuizCountdown(id, quizId, resume)——resume=false 首次裁决（已有 deadline 直接复用，幂等防多端重置）、resume=true 以冻结剩余量为基准重新续算；saveQuizRemainingSeconds 同步推进 deadlineAt；新路由 POST /:id/quiz/:quizId/countdown/start（resume 严格布尔校验）
- 前端：studynotesApi 增加 startQuizCountdown；useQuizCountdown 新增 cardId/canStartCountdown 入参，删除本地 Date.now()+快照 起算逻辑，改为读服务端 deadline；状态机新增 frozen 态（LOAD_SUCCESS 时 deadlineAt 非空 → frozen，否则 answering），新增 resume()；QuizModalEditor 确认栏加 resume 动作「继续答题」，QuizBody 只读条件加 frozen
- 关键坑（两处，均为实现中自查发现）：
  1. 冻结态不可用 deadlineAt 计算——绝对时刻会随真实时间自然流逝，冻结态停留超截止时刻会误触发 onTimeUp 自动交卷（家长端仅查看却替孩子提交）。修法：冻结态独立取 quiz.remainingSeconds 定格，不判超时、不触发 onTimeUp、文案按 mm:ss 定格不显示「时间已到」
  2. resume 后不能复用旧 deadline——服务端幂等分支直接返回旧值会让关闭期间流逝的时间被计入。修法：进入作答态且持有冻结剩余量且未发起过请求时，以 resume=true 显式续算；续算失败回退既有 deadline

## 修复：多端倒计时互相劫持（A 作答中 B 端观测定格）

- 现象：用户 A 正在答题且倒计时正常计时，用户 B 从其他客户端打开同一测验，显示的是 A 的倒计时内容而非定格
- 根因：`remainingSeconds`（剩余量快照）与 `deadlineAt`（绝对截止时刻）语义重叠打架。A 作答中库里 `remainingSeconds` 恒为陈旧值（满额/上次冻结量），B 端加载时 `deadlineAt` 非空使其进冻结态，却用陈旧快照定格展示 → 显示与 A 无关的数字；更危险的是 B 端点「继续答题」时 `active` 转 true，原 `shouldResume` 条件成立，据陈旧快照重新裁决 `deadlineAt`，**把 A 正在跑的计时整个重置**（极端情况重置回满额 45 分钟）
- 方案：让二者语义正交——`deadlineAt` 非空 = 计时进行中（多端唯一真源）；`deadlineAt` 为空且 `remainingSeconds` 非空 = 计时已暂停（本端曾冻结）
- 服务端：saveQuizRemainingSeconds 冻结时由「推进 deadlineAt」改为「清空 deadlineAt」，用 null 明确表达计时已暂停
- 前端：冻结态定格基准改为优先按 `deadlineAt` 取打开瞬间剩余量（旁观态如实反映 A 读数且不 tick、不判超时），仅 `deadlineAt` 为空时回退冻结快照；`getRemainingSeconds` 非激活态一律返回 null，避免旁观端关闭弹窗时写库而暂停他人计时（新增 activeRef 镜像，保持函数引用恒定）
- 自查纠正（实现中发现并回退）：初版新增的 `isPaused`/`shouldResume` 续算分支是**死代码**——`quiz.deadlineAt === null` 分支在上方已 early return，该判断恒为 false；已删除整块，暂停态由既有首次裁决路径处理（服务端以落库快照裁定，效果等同续算）
- 顺带修正：新测验 generateQuiz 插入时即写入满额 remainingSeconds，故「两者皆空才进 answering」的旧注释不符事实；LOAD_SUCCESS 冻结判定已覆盖该情形并更正注释
