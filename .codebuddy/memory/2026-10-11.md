## 部署形态：题目目录移出 deploy 的重构
- 问题：`library/` 默认落在运行目录内，而 `pnpm package` 会整体删除重建 `deploy/`，覆盖式部署会连带清掉题目。
- 改动（`server/src/paths.ts`）：抽出内部 `resolveRuntimeDir(dirName)`，`resolveDataDir()` 改为调用它以消除重复；新增导出 `resolveLibraryDir()`，与数据库同一套「仓库内试跑（产物目录名为 deploy）时自身目录不存在则回退仓库根」规则。
- 改动（`server/src/routes/library.ts`）：默认目录由 `resolveFromRoot('library')` 改为 `resolveLibraryDir()`，头部注释与函数注释同步。
- 文档（README）：功能列表与「本地题目」章节说明回退行为；「部署注意事项」对应行改为「本地题目目录须部署在产物目录之外」，要求生产环境改配部署目录之外的绝对路径（与 `DB_PATH` 的建议一致）。
- 说明：显式设置 `APP_ROOT` 会关闭回退分支（与 data/.env 行为一致），故生产环境（部署目录名非 deploy）不会自动回退，必须显式配置绝对路径；该回退分支与 data 共用同一实现。
- 验证：`server tsc --noEmit` 通过；路径解析实测 —— 开发态 `data`=仓库根/data、`library`=仓库根/library（说明重构未改变 data 行为）；`APP_ROOT` 显式指向临时目录时两者均落在该目录下且不回退。

## 题库目录规则修订：与 data 目录同级
- 起因：要求题库目录「与 data 目录同级，不管在服务器还是在哪都一样」。
- 实现（`server/src/routes/library.ts`）：新增内部 `resolveDefaultLibraryDir()`，取 `path.dirname(path.dirname(DB_FILE_PATH))/library` —— 数据库文件所在目录（data）的父目录下的兄弟目录；未配置 DB_PATH 时等价于 `<APP_ROOT>/library`，仓库内试跑时随 data 一起回退到仓库根；内存库（DB_FILE_PATH 为 null）回落 `resolveDataDir()` 保持同一语义。
- 回滚（`server/src/paths.ts`）：上一版新增的 `resolveRuntimeDir` 抽取与 `resolveLibraryDir` 导出撤销，恢复原 `resolveDataDir()` 实现——题库改为一律跟随数据库文件位置，不再需要独立解析函数。
- 文档（README）：功能列表、「本地题目」章节、「部署注意事项」表统一为「与 data 目录同级并随 DB_PATH 迁移」，示例 `DB_PATH=D:\study-plus\data\study.db → 题库 D:\study-plus\library`。
- 注意：若 DB_PATH 指向较深目录（如 `D:\study-data\study.db`），同级规则会得出 `D:\library`，此情形需在「系统设置 → 本地题目目录路径」显式配置。
- 验证：`server tsc --noEmit` 通过；实测两场景 —— 未设 DB_PATH 时 data=`<repo>/data`、library=`<repo>/library`（与现有题目位置一致）；`DB_PATH=...\ext\data\study.db` 时 library=`...\ext\library`（兄弟目录）。
