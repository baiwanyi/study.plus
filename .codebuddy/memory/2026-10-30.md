# 2026-10-30 工作记录

## 修复：图片出题被「未配置视觉模型」拦截（503）

### 问题

题库「AI 生成题目」附带参考图片时返回 503：

```
图片出题未配置视觉模型，请先在服务端设置 DEEPSEEK_VISION_MODEL
```

原因是代码按旧认知把视觉能力视为需要独立实验模型的档位（`DEEPSEEK_VISION_MODEL` 缺省为空字符串），
带图请求在路由层与服务层各做了一次「未配置即失败」的前置校验。实际 DeepSeek 官方视觉指南已明确：
`deepseek-flash`（V4.1-Flash）原生接收 `image_url` 分片，旧的 `deepseek-v4-flash-vision-exp`
虽仍被接受但对应模型已退役，官方建议直接用 `deepseek-flash`。

### 改动

- 视觉档位由「缺省空串」改为「缺省复用 `DEEPSEEK_MODEL`」，仅在确实需要图片走另一档模型时才用
  `DEEPSEEK_VISION_MODEL` 覆盖
- 删除路由层与服务层的两处「未配置视觉模型即 503 / 抛错」前置校验
- 同步更新 `server/.env.example` 说明与相关注释（含前端入参注释）

### 官方视觉能力契约（供后续维护核对）

- 模型名：`deepseek-flash`；图片随 user 消息以 `image_url` 分片发送，出现在 system/assistant 消息返回 400
- 支持格式：JPEG / PNG / GIF / WebP（按文件实际内容识别）；单图 ≤ 32 MiB（内联 data URL）
- 单请求请求体 ≤ 48 MiB，图片数上限 600 张，单图按 1024 tokens 上限计费
- 项目现状已合规：最多 9 张、单张约 1.1MB、仅 PNG/JPEG/WebP、仅 user 消息

### 涉及文件

- `server/src/services/ai/core.ts`（修改）：视觉档位缺省回落 `DEEPSEEK_MODEL`，更新头部与常量注释
- `server/src/services/ai/library.ts`（修改）：移除缺视觉模型的抛错，model 选择改为按有无图片判断
- `server/src/routes/library.ts`（修改）：移除 503 拦截与无用导入，更新头部注释
- `server/.env.example`（修改）：视觉模型档位说明改为「留空复用 DEEPSEEK_MODEL」
- `apps/src/services/library.ts`（修改）：`images` 字段注释更新
