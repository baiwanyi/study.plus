# 2026-10-30 工作记录

## 修复：图片出题被「未配置视觉模型」拦截（503）

### 问题

题库「AI 生成题目」附带参考图片时返回 503：

```
图片出题未配置视觉模型，请先在服务端设置 DEEPSEEK_VISION_MODEL
```

原因是代码按旧认知把视觉能力视为需要独立实验模型的档位（`DEEPSEEK_VISION_MODEL` 缺省为空字符串），
带图请求在路由层与服务层各做了一次「未配置即失败」的前置校验。实际 DeepSeek 官方视觉指南已明确：
`deepseek-flash`（V4.1-Flash）原生接收 `image_url` 分片，旧的 `deepseek-v4-flash-vision-exp`
虽仍被接受但对应模型已退役，官方建议直接用 `deepseek-flash`。

### 改动

- 视觉档位由「缺省空串」改为「缺省复用 `DEEPSEEK_MODEL`」，仅在确实需要图片走另一档模型时才用
  `DEEPSEEK_VISION_MODEL` 覆盖
- 删除路由层与服务层的两处「未配置视觉模型即 503 / 抛错」前置校验
- 同步更新 `server/.env.example` 说明与相关注释（含前端入参注释）

### 官方视觉能力契约（供后续维护核对）

- 模型名：`deepseek-flash`；图片随 user 消息以 `image_url` 分片发送，出现在 system/assistant 消息返回 400
- 支持格式：JPEG / PNG / GIF / WebP（按文件实际内容识别）；单图 ≤ 32 MiB（内联 data URL）
- 单请求请求体 ≤ 48 MiB，图片数上限 600 张，单图按 1024 tokens 上限计费
- 项目现状已合规：最多 9 张、单张约 1.1MB、仅 PNG/JPEG/WebP、仅 user 消息

### 涉及文件

- `server/src/services/ai/core.ts`（修改）：视觉档位缺省回落 `DEEPSEEK_MODEL`，更新头部与常量注释
- `server/src/services/ai/library.ts`（修改）：移除缺视觉模型的抛错，model 选择改为按有无图片判断
- `server/src/routes/library.ts`（修改）：移除 503 拦截与无用导入，更新头部注释
- `server/.env.example`（修改）：视觉模型档位说明改为「留空复用 DEEPSEEK_MODEL」
- `apps/src/services/library.ts`（修改）：`images` 字段注释更新

### 验证结果

- `pnpm --filter server exec tsc --noEmit`：无错误
- `pnpm --filter server exec vitest run __test__/library-paper.test.ts`：12 项全部通过
- 未做接口级实测（需真实 API Key 与图片，由用户在运行环境验证）

## 调整：题库文件列表按修改时间降序

### 需求与取舍

侧边栏清单原按路径自然序（`01-`、`02-` 这类前缀）排列。改为按文件修改时间降序后，最近做过的题目排在最前。
排序放在服务端列表接口而非侧边栏组件内，原因是键盘左右键翻页与 `?file=` 失效时的「回落首份」都直接
复用同一份 `files` 顺序，前端单独排序会让侧边栏序号与翻页次序不一致。

### 改动

- 列表接口排序改为 `mtime` 降序，同一时间戳以路径自然序兜底，保证顺序稳定可复现
- 同步更新服务端模块头注释与侧边栏头注释（说明次序由服务端提供）

### 涉及文件

- `server/src/routes/library.ts`（修改）：清单排序逻辑与头部注释
- `apps/src/pages/Library/components/LibrarySidebar.tsx`（修改）：头部注释说明清单次序来源

### 验证结果

- `pnpm --filter server exec tsc --noEmit`：无错误
- `pnpm exec vitest run __test__/library.e2e.test.ts`：6 项全部通过（用例用 arrayContaining 断言，不依赖顺序）

## 新增：邮件备份连题库目录一起打包

### 需求与取舍

备份原本只打包数据库快照。题库（Markdown 题目与图片）落在磁盘目录而非库里，只备份库无法恢复题目。
题库根目录的解析逻辑原先私有在题库路由内，备份要用同一套推导（配置值 → 绝对路径 → 默认与 data 同级，
测试内存库回落 resolveDataDir），故抽成共用模块，避免两处各写一份导致备份与页面指向不同目录。

### 改动

- 新增题库根目录解析模块，题库路由与备份服务共用；路由侧删除原私有的默认目录与解析实现
- 备份打包追加题库目录，压缩包内以 `library/` 为根，递归只收普通文件并跳过软链（防止把题库之外的文件带进附件），层级超 20 层停止
- 题库目录不存在时只打包数据库，备份邮件正文按实际收录内容说明
- 邮件主题前缀、附件名、保留策略均保持不变

### 涉及文件

- `server/src/services/library-root.ts`（新增）：题库根目录解析
- `server/src/services/backup.ts`（修改）：打包题库目录、邮件正文与头注释
- `server/src/routes/library.ts`（修改）：改引用共用解析模块，删除私有实现
- `server/src/index.ts`（修改）：调度注释与日志文案
- `server/.env.example`（修改）：`BACKUP_MAX_ATTACHMENT_MB` 说明补充题库体积
- `server/__test__/backup.test.ts`（修改）：新增题库打包与目录缺失两个用例，题库根目录 mock 为不存在路径
- `README.md`（修改）：产品特性、目录树、Phase 11、备份章节与环境变量表

### 验证结果

- `pnpm --filter server exec tsc --noEmit`：无错误
- `pnpm exec vitest run __test__/backup.test.ts`：12 项全部通过（新增用例 11 校验 zip 内含 `library/` 子目录文件，用例 12 校验目录缺失时只打包库）
- `pnpm test`（服务端全量）：10 个测试文件 86 项全部通过
- 未做真实邮件发送实测（需 SMTP 配置，由用户在运行环境验证）
