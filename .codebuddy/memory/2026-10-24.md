## 调整：入口紧跟题目正文 + 解题思路持久化到题目文件
- 需求补充：按钮不要放在最右边，要直接跟在题目后面；已获取的解题思路要保存进当前题目文档，方便二次查看（不再重复请求 AI）。
- 数据格式（写回题目 .md 末尾）：
  ```
  <!-- library-hints:start -->
  ## 解题思路

  <!-- hint:3 -->
  ### 一、填空题 · 第 3 题

  （AI 正文）
  ```
  区块起始用 HTML 注释标记（比「找同名标题」可靠），单题用 `<!-- hint:N -->` 分隔（N 为小题块索引，稳定键）；渲染时注释被 rehype-raw 丢弃。
- 实现（`shared/src/utils.ts`）：
  - `parseLibraryQuestions` 的块新增 `section`（最近标题文本，去掉「（每空2分…）」分值说明），用于生成条目标题。
  - 新增 `splitLibraryHints(markdown)` → `{ body, tail, hints }`：以注释标记定位区块，区块到「下一个其它二级标题或文件尾」结束；`tail` 保留区块之后的用户内容，写回时不得丢失；条目按 `<!-- hint:N -->` 聚合，重复索引后者覆盖。
  - 新增 `upsertLibraryHint(markdown, { index, number, section, content })`：覆盖同名索引、按索引升序重排、重建区块并拼回 `body + 区块 + tail`；写回前归一化 CRLF、写完按原文件风格还原（实测还原后无游离 LF）。
  - 新增 `stripLibraryHintHeading(markdown)`：只剥离 `### … 第 N 题` / `### 整篇题目` 这类条目标题，不会误删 AI 正文的 `### 一、读懂题目`。

## 修复：思路面板底色与内容被截断
- 现象：面板整体淡黄底；思路停在小节中间（实测停在「四、易错提醒 · 容易」）。
- 背景（`LibraryQuestion.tsx`）：去掉面板的 `bg-amber-50/60`，只留 `border-amber-200`；`.wmde-markdown` 的透明底沿用 `markdown-viewer.css` 既有规则。
- 截断根因：`core.ts` 的截断重试仅对 JSON 调用生效（`truncated = finishReason === 'length' && expectsJson`），纯文本调用直接返回半截内容；而解题思路 `max_tokens` 只给了 1600，五节内容（含推理 token）不够。
- 实现（`server/src/services/ai/core.ts`）：`CallDeepSeekResult` 增加可选 `finishReason`，纯文本调用方据此自行决定是否扩容。
- 实现（`server/src/services/ai/library.ts`）：常规预算 1600 → 4000；检测到 `finishReason === 'length'` 时以 8000 重试一次，并附「必须完整输出五节、每节 2~4 条、每条 ≤40 字、不许中途停住」的约束。
- 实现（`shared/src/constants.ts`）：`defaultPromptLibraryHint` 末尾补「篇幅要求」——五节必须写完、全文 600 字以内，从源头降低截断概率。
- 实现（`shared/src/utils.ts` + 组件）：新增 `isLibraryHintComplete`（检测末节「自查清单」）；已保存内容不完整时面板提示「可点『换一种思路』重新生成」，不自动重生成以免重复计费。
- 验证：`server` / `apps` `tsc --noEmit` EXIT 0；IDE 诊断 0 错误；`pnpm --filter apps build` 成功。
- 待用户确认：旧版本已保存的截断内容不会自动更新，需点「换一种思路」覆盖（或手动删除文件里 `<!-- library-hints:start -->` 之后的区块）。

## 修复：思路面板内的分数与公式不渲染
- 原因：`prepareLibraryContent`（`\(…\)`→`$…$`、`\frac`→`\dfrac`）只在页面加载时对文件全文执行一次；新生成的思路来自接口原文，未过预处理就直接交给 `MarkdownView`，而 remark-math 只认 `$` 定界符 → AI 输出的 `\( … \)` 显示为裸 LaTeX。
- 实现（`apps/src/pages/Library/index.tsx`）：顺序改为「先 `splitLibraryHints` 剥离思路区（原文）→ 再对正文 `prepareLibraryContent`」，思路正文交由题块组件自行预处理，避免同一份内容被处理两次。
- 实现（`apps/src/pages/Library/components/LibraryQuestion.tsx`）：新增 `displayBody = useMemo(() => prepareLibraryContent(body), [body])`，已保存内容与刚生成内容走同一条预处理链路。
- 不能双重预处理的证据（实测）：同一段选项文本处理一次得 2 个 `library-line-space` 撑高元素，处理两次变 4 个（行盒被重复撑高），故必须保证「每份内容只预处理一次」。
- 归一化实测：`\( \frac{1}{10} \)` → `$ \dfrac{1}{10} $`；同行 `\[ … \]` → `$$ \dfrac … $$`；独占行 `$$ … $$` 保留 `\frac`；行内 `$$ … $$` → `\dfrac`。
- 验证：`server` / `apps` `tsc --noEmit` EXIT 0；`pnpm --filter apps build` 成功。
