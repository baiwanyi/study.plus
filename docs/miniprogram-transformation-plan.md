## 0. 执行摘要

**三项已确认的方向性决策**

| # | 决策 | 落地含义 |
| --- | --- | --- |
| 1 | **不保留 Web 端，新建项目** | 产品形态只有微信小程序；新建一个独立仓库承载全部代码；`study.webian.dev` 转为归档仓（只保留源码、文档与历史），不再发版、不做 Web 兼容层、不迁移 v2 代码与数据 |
| 2 | **走 CloudBase** | 后端、数据库、存储、AI、定时触发、环境隔离全部使用腾讯云开发；不自建服务器、不引入 Express / SQLite / React / 本地文件系统 |
| 3 | **包月 + 消费积分** | 用户包月获得每月消费积分，AI 等能力按积分消耗，积分耗尽可购买积分补充包；权益与账务以**消费积分账本**为唯一真实来源 |

**对既有资产的处理**：`study.cloudbase`（v3.0 小程序工程）降级为**参考实现**——可迁移其 TDesign 页面骨架、组件、AI 提示词与规则语义；认证、租户隔离、积分账本、计费四个地基因存在结构性问题（见 1.5），**在新项目里重写而非整体 fork**。v2 只提供业务语义与语料，不提供代码。

**计费模型一句话**：包月是「订阅入口」，消费积分是「站内唯一通行额度」，补充包是「用尽后的加购」；所有 AI 能力按统一价目表扣分，服务端预扣 + 结算 + 幂等，客户端余额仅用于展示。

**必须提前锁定的合规点**：该模型属于微信虚拟支付的**代币模式（`short_series_coin`）**典型场景（先获得额度、高频小额多次消费）。平台要求「代币兑换比例发布后不可修改，上线前必须评审并沙箱验证」，且必须做「发货回调 + 主动查单」双通道兜底。因此**积分与人民币的兑换比例、积分价目表、有效期与结转规则属于上线前不可回退的配置，须在 Gate 0 冻结**。

**首发范围**：家庭场景、包月订阅制、家长与孩子双端可登录、单家庭数据严格隔离；团队/学校版、练字原生移植、本地题库、v2 数据迁移明确列为 Non-Goals。

**预计周期**：Gate 0 至 M4 上线约 12–16 周（M2 与 M3 并行），按 1 前端 + 1 后端 + 0.5 测试/设计估算；比 v1.0 略增，主要来自积分账本与支付模式的额外工作量。

### 1.3 新项目技术架构（全量 CloudBase）

```
[微信小程序 · 原生 + TDesign 1.15]
   │ wx.cloud.callFunction（免配置服务器域名）
   │ wx.requestVirtualPayment / wx.requestAppleSubscribeSign
   ▼
[CloudBase 云函数 · Node.js 20 + TypeScript]
   ├─ common/ Layer：auth / db / scope / entry / errors / ai / credit
   ├─ 业务函数：auth / family / tasks / points / exchanges / advances / weekly / study / options / privacy
   ├─ 计费函数：billing（订单发货）/ entitlement（权益裁决）/ credit（积分账本）/ notify（对账补单）
   └─ 定时器：月度积分发放、月度还款、积分过期、日终对账、成本熔断巡检
   ▼
[CloudBase MySQL 8.0]      [CloudBase NoSQL]       [云存储 + CDN]      [CloudBase AI]
  业务数据 + 积分账本        租户级配置/规则           图片/字体/分享素材     deepseek 系列模型
```

| 层 | 选型 | 关键约束 |
| --- | --- | --- |
| 小程序端 | 微信原生框架 + TDesign Miniprogram；TypeScript；4 Tab + 分包 | 主包 ≤2MB、总包 ≤20MB；`lazyCodeLoading`；PC 侧边栏复用 v3 方案 |
| 云函数 | Node.js 20 + TypeScript 严格模式，`common/` 作为 Layer；统一入口 `run()` 包装异常与响应格式 | 云函数**多实例**，任何限流、计数、余额都不得用进程内存 |
| SDK | **`@cloudbase/js-sdk` v3**（Node 端能力已覆盖云函数场景） | 禁止引入已停止维护的 `@cloudbase/node-sdk`；禁止把任何密钥放进小程序端 |
| 关系库 | CloudBase MySQL 8.0 + 参数化查询 | 所有 SQL 参数绑定；积分账本使用事务 + CAS；连接信息全部环境变量注入 |
| 配置库 | CloudBase NoSQL（`options` / `rules` / `categories` / `credit_price_list`） | 文档 key 必须带 `family_id` 前缀或字段，禁止全局单例 |
| 存储 | 云存储 + CDN | 字体、题库图片、分享背景、字帖图为远程资源，不进小程序包 |
| AI | CloudBase AI 托管模型（`ai.createModel` 传 GroupName，模型 ID 在 `generateText` 的 `model` 字段） | 调用前核验小程序成长计划与 Token Credits 资源包资格；无第三方 API Key 外泄面 |
| 身份 | `cloud.getWXContext().OPENID / UNIONID`，仅服务端可信 | 严禁从 `event.openid` / 客户端参数取身份 |
| 环境 | dev / staging / prod 三个 EnvId 显式指定 | 计费与积分配置按环境隔离，禁止共用同一支付商户号做测试 |
| 定时触发 | CloudBase 定时触发器 | 月度积分发放与还款、积分过期、日终对账、预算熔断，全部幂等可重跑 |

### 1.5 新项目必须避免的历史缺陷（设计约束）

> 以下不是「待修 Bug」，而是**新建代码的验收约束**。v3 的这些问题正是地基重写的原因。

| # | 历史缺陷 | 新项目约束 |
| --- | --- | --- |
| 1 | 信任客户端 `event.openid`，全仓无 `getWXContext()` | 身份只允许来自云上下文；伪造 openid 的用例必须返回 401 |
| 2 | 所有登录者注册为 `parent`，孩子是伪 openid 档案 | 账号 `members` 与孩子档案 `child_profiles` 分离 |
| 3 | JWT 30 天仅验签、无吊销 | access + refresh + `token_version`，停用即时失效 |
| 4 | 使用已废弃 `wx.getUserProfile` | 头像昵称填写能力 |
| 5 | NoSQL `options` / `rules` 全局单例 | 配置按 `family_id` 隔离 |
| 6 | `userFilter` 字符串拼接 | 全参数化查询 |
| 7 | 依赖 `@cloudbase/node-sdk` | 只用 `@cloudbase/js-sdk` v3 |
| 8 | 隐私导出漏消息表、删除不彻底 | 导出/删除表清单与 DDL 自动比对 |
| 9 | 缓存 key 未含身份维度 | 缓存键必须包含 `familyId + childId + userId` |
| 10 | 无内容安全、无 AI 标识、无订阅消息 | 列为 M3 上线门禁 |
| 11 | README 误称「无需服务器 / 域名 / 备案」 | 备案与业务域名列为上线前置条件 |

## 2. 功能梳理与小程序端设计

### 2.1 功能取舍

**目标（上线后 3 个月）**：一个可审核上线、可包月收费、积分账务零差错、家长与孩子各自可登录、单家庭严格隔离的微信小程序。

| 优先级 | 功能 | 理由 |
| --- | --- | --- |
| P0 | 登录与隐私同意、家庭/成员/孩子、作业与成长积分闭环、兑换预支、周报、心得与测验、分享、**消费积分账本 / 包月 / 补充包 / 账单**、AI 能力按分扣减、内容安全与 AI 标识、导出/注销 | 构成可上线、可收费的最小闭环 |
| P1 | 订阅消息提醒、用量与成本看板、多家长邀请、云端题库（只读）、积分消耗明细与低余额提醒 | 留存与运营 |
| P2（M5+） | 20 题测验 + 错题本、学习中心、AI 出卷、字帖图片、跨孩子趋势、团队/班级版 | 非上线阻断 |

**明确不做（Non-Goals）**

1. **任何 Web 端**：无 Web 前台、无 H5 付费、无双端同步、无 v2 兼容层。
2. **v2 代码与数据迁移**：不迁移 React / Express / SQLite 代码，不提供 SQLite 导入工具。
3. **A4 字帖原生打印**：约 27MB 字体超包体积限制，且小程序无打印 API；后续仅做云端图片。
4. Markdown / Mermaid / KaTeX 全量渲染链：改 `rich-text` 白名单、服务端安全 HTML、公式图片化。
5. 本地文件系统与邮件 zip 备份：改云存储 + 云数据库快照。
6. 自建账号密码体系：微信身份为唯一凭据。
7. 首年广告变现、积分提现、积分转让、积分反向兑现金。

### 2.2 小程序交互基线

| 维度 | 设计 |
| --- | --- |
| 导航 | 4 Tab（首页 / 作业 / 成长积分 / 我的）+ 二级页；全局孩子切换器；PC 端侧边栏布局 |
| 双积分入口 | 「成长积分」在积分 Tab；「消费积分」在「我的 → 我的额度」，两者页面、图标、文案、账本完全分离（见 2.4） |
| 长表单 | 原生 `<editor>` + 本地草稿 + 离页保存；服务端不信任客户端草稿 |
| AI 调用前 | 展示「本次预计消耗 N 点，当前余额 M 点」确认；余额不足时引导补充包或包月，**不阻断查看已生成内容** |
| 富内容 | `rich-text` 白名单 / 服务端转安全 HTML；公式与思维导图走图片或 web-view |
| 分享 | Canvas 2D → `wx.saveImageToPhotosAlbum`；导出图片带 AI 生成显式标识、元数据带隐式标识 |
| 缓存 | key 含 `u<userId>:f<familyId>:c<childId>:`；401 清缓存并 `reLaunch` 登录页 |
| 管理页 | 服务端 `assertRole` 裁决，前端仅做可见性；付费入口只在 owner 端展示，孩子端零营销 |

### 2.3 平台能力映射

| 能力 | 用法 | 约束 |
| --- | --- | --- |
| 身份 | `cloud.getWXContext().OPENID / UNIONID` | 服务端唯一可信来源 |
| 头像昵称 | `<button open-type="chooseAvatar">` + `<input type="nickname">` | 不用已废弃 API |
| 包月订阅 | 安卓/鸿蒙/Windows 会员订阅；iOS `wx.requestAppleSubscribeSign` | 自动续费显著提示；iOS 由 Apple 扣费 |
| 积分补充包 | 微信虚拟支付；**优先评估代币模式 `short_series_coin`**，若平台认定为单品交付则走道具模式 `short_series_goods` | 兑换比例发布后不可修改；回调 + 查单双通道兜底 |
| 内容安全 | `msgSecCheck` / `mediaCheckAsync` | UGC 与 AI 输出全量 |
| 触达 | 一次性订阅消息（积分低余额、订阅到期、作业提醒） | 禁止首页硬弹、禁止营销滥用 |
| 存储 / 云调用 | 云存储 + CDN；`wx.cloud.callFunction` | web-view 需已备案业务域名 + 校验文件 |
| 其他 | 扫码加入家庭、剪贴板、Canvas 2D、相册 | 相册拒绝授权降级为预览 |

### 2.4 两套积分必须严格隔离（关键设计）

产品内同时存在两种「积分」，若混淆会同时引发**用户误解**与**合规风险**（付费额度被误认为可兑现、或成长积分被误认为可购买 AI 服务）。

| 维度 | 成长积分（学习激励） | 消费积分（付费额度，对外建议称「AI 点」） |
| --- | --- | --- |
| 获取 | 家长按作业等级、考试分数、自定义规则加减；每月初始 500 分 | 包月每月发放、积分补充包购买、新用户体验赠送 |
| 用途 | 兑换娱乐时间 / 现金奖励（**家长线下兑现，平台不做资金结算**）、预支分期 | 仅用于消耗 AI 能力与其他按量服务 |
| 账本 | `point_records` / `month_summary` / `point_advances`（按 `child_id` 独立） | `credit_accounts` / `credit_ledger`（按 `family_id` 统一） |
| 所有权 | 归属孩子 | 归属家庭（owner 管理） |
| 是否可购买 | **否** | 是 |
| 是否可提现 / 转让 / 反向兑人民币 | 否（现金奖励由家长线下处理，系统只记录） | **否，明令禁止** |
| 是否可互换 | **否，两套账本永不互通** | 否 |
| UI | 积分 Tab，成长/激励语境，儿童可见 | 「我的 → 我的额度」，钱包/账单语境，仅家长可见 |

落地要求：数据库表、云函数、API 字段、前端组件、文案、图标、通知模板全部命名隔离（成长积分用 `points`，消费积分用 `credits`）；用户协议与《消费积分规则》中写明性质、有效期、退款折算与停服处理；**成长积分的「兑换现金」文案不得出现「提现」「余额」「充值」等金融化表述**。

## 3. 多用户管理体系

设计基线沿用 `docs/multi-user-plan.md` 的三层模型与 RBAC + 数据范围双层校验，登录部分按微信生态重写。

### 3.1 概念模型

```
organization（可选，团队 / 机构版，M5+）
   └── family（家庭 = 租户 = 计费主体 = 消费积分账户主体）
          ├── members（微信账号：owner / parent / child / teacher）
          ├── child_profiles（孩子档案 = 成长积分与学习数据归属主体）
          ├── subscription（包月套餐、周期、状态）
          ├── credit_account（消费积分余额、版本）
          └── 业务数据（family_id 隔离 + child_id 归属）
```

**账号与孩子档案分离**：`members` 是真实微信身份，承载登录与角色；`child_profiles` 是家长创建的学习主体，承载成长积分、作业、周报与测验。孩子可用自己的微信绑定登录，也可由家长用「家庭码 + 6 位 PIN」在同一设备上进入，业务数据始终归属该孩子。

### 3.2 账号与登录鉴权

| 项 | 设计 |
| --- | --- |
| 家长注册 | `wx.cloud.callFunction` → 服务端 `getWXContext().OPENID` → 建 `member(role=owner)` + `family` + 第一个 `child_profile` + `credit_account` + 体验积分 |
| 孩子登录 | 推荐「家庭码 + 昵称 + 6 位 PIN」；可选孩子微信扫码绑定（需监护人单独同意）；可选家长设备内快速切换 |
| 第二家长 | 一次性邀请码（24h、单次、绑定 `family_id`），角色 `parent`；不可停用 owner |
| 令牌 | access 30 分钟 + refresh 30 天（`sessions` 表滚动轮换），载荷 `sub / fid / role / tv` |
| 吊销 | `members.token_version` 递增，验签后比对；停用 / 重置 PIN / 退订即时失效 |
| 风控 | 登录 / PIN / 邀请码分别限流；PIN 5 次失败锁定 15 分钟；频控计数落库（云函数多实例） |
| 隐私同意 | 首次登录强校验版本；不满 14 周岁儿童信息由监护人单独同意并留痕 `consent_records` |

### 3.3 角色权限（RBAC + 数据范围）

| 权限点 | owner | parent | child | 说明 |
| --- | --- | --- | --- | --- |
| 作业 布置 / 删除 / 评分配置 | 是 | 是 | 否 | 孩子可提交、查看、发起自己的 AI 评分（消耗家庭消费积分，受额度约束） |
| 成长积分 加减 / 规则修改 | 是 | 是（不改规则） | 否 | 规则变更写 `audit_logs` |
| 兑换 / 撤销 / 预支 | 是 | 是 | 申请 | 建议演进为「孩子申请 → 家长批准」 |
| 周报 / 心得 / 测验 | 读写全部孩子 | 读写全部孩子 | 仅自己 | 测验走服务端 deadline 裁决 |
| 分享 / 题库 | 是 | 是 | 是 | 只读共享资源 |
| **消费积分 查看** | 是 | 只读 | **不可见** | 孩子端不展示钱包与付费入口 |
| **消费积分 消费 / 包月 / 补充包 / 账单** | **是（独占）** | 否 | 否 | 付费动作仅 owner；parent 只读余额 |
| 成员 / 套餐 / 数据导出 / 注销 | 是 | 否 | 否 | 监护人行使 |

实现三层：`run()` 统一入口 → `getAuthContext()` 生成参数化隔离条件 → `assertRole()` + `assertPermission()`；写操作前 `requireTargetChild()`。**前端隐藏按钮不是安全边界。**

### 3.4 数据隔离

1. 所有 MySQL 业务表带 `family_id`（隔离）+ `child_id`（归属）；跨家庭访问按「不存在」处理。
2. NoSQL 配置 key 带 `family_id` 前缀，杜绝跨家庭串规则。
3. 唯一索引按孩子 / 家庭维度重建：`(family_id,key)`、`(child_id,month)`、`(child_id,year,week_number)`、`(child_id,subject,topic)`。
4. 越权面清单（列表 GET、所有 `/:id` 写操作、预支、兑换撤销、测验提交、**积分消费与账本查询**、规则修改）逐个断言并配集成测试。
5. 定时任务按 `child_id` 分组遍历（月度还款、月度汇总）。
6. 缓存 key 含身份三元组；`credit_account` 查询强制带 `family_id`。
7. `audit_logs` 记录登录失败、成员变更、规则修改、**积分发放/消耗/退款**、订阅与隐私操作；日志脱敏。

### 3.5 组织与团队

- **V1**：家庭一级 + 多家长；家庭码、邀请码、成员停用/启用、孩子切换器。
- **V2（M5+）**：`organizations` + `teams/classes` + 席位 + `teacher`；组织订阅与家庭订阅互斥、消费积分池归属明确。V2 前不做跨家庭共享。

### 3.6 数据迁移

**本项目无历史数据迁移**：不迁移 v2 SQLite、不导入 v3 MySQL。新项目从空库启动，仅导入静态内容资产（积分规则默认值、AI 提示词、题库/字帖语料、分享背景）。这项决策显著降低 Gate 0 与 M1 的风险和工作量。

## 4. 收费模式设计：包月消费积分

### 4.1 平台规则与模式选择（2026 年）

| 规则 | 内容 | 对本方案的影响 |
| --- | --- | --- |
| 虚拟支付强制 | 会员订阅、付费功能、AI 生成、在线教育 / 效率工具均属虚拟商品；须全终端（iOS / Android / Windows / 鸿蒙）接入小程序虚拟支付，**不得引导至 App / 公众号 / H5 / 个微 / 网站支付** | 无 Web / H5 付费页，与「不保留 Web 端」一致 |
| 生效时间 | 2026-02-27 规范更新，2026-04-01 前须完成全终端接入 | 上线阻断项，Gate 0 即启动开通申请 |
| **两种商品形态** | **代币模式 `short_series_coin`**：先充值再消费，适配高频多次小额，需余额 / 流水 / 补偿，复杂度高；**道具模式 `short_series_goods`**：单次购买单次交付，链路短 | 本模型是「先获得额度、按次扣减」的余额体系 → **主路径按代币模式设计与申报**；补充包若被平台认定为固定点数包，可走道具模式 |
| **兑换比例不可改** | 代币兑换比例发布后不可修改，上线前必须评审并沙箱验证 | **积分:人民币比例、补充包面额、AI 价目表必须在 Gate 0 冻结并沙箱验证**，属于不可回退配置 |
| 账务一致性 | 典型风险为「兑换比例与账务一致性」 | 账本以服务端为唯一真实来源，日终对账、幂等、补偿 |
| 双通道兜底 | 不管哪种模式，都要做「发货回调 + 主动查单」；不得把前端 `success` 当最终成功 | 见 4.6 |
| 计价单位 | 接口与后台金额统一用「分」 | 定价与订单字段以分为单位 |
| 双端余额 | 平台代币存在 iOS / 安卓余额不互通的规则；商家自研代币的双端互通性以官方最新文档核定 | `credit_ledger` 预留 `platform` 字段，账本可按平台分账，避免后期返工 |
| 费率（工具类当前生效） | Android / 鸿蒙 / Windows：主动支付标准 10%、当前 1%；会员订阅首笔 1%、第二笔起 10%。iOS：标准 17%（含 Apple 12%）、当前 12%（腾讯 5% 暂减免） | 按标准费率 10%~17% 做保守成本模型 |
| iOS 会员订阅 | Apple 周期自动扣费，用户在 App Store 退订；**商家无法主动退款**；账期长 | 退款与客服流程分端设计 |

> 费率、准入类目与版本要求以微信开放文档最新公告为准；代币比例、双端互通性须在开通虚拟支付时向平台确认并留档。

### 4.2 计费模型总览

```
包月订阅（自动续费）
   └─ 每月 1 次发放「消费积分」到家庭账户 ──┐
积分补充包（一次性购买，用完即买）  ────────┼──▶  credit_account（家庭唯一余额）
新用户一次性体验积分（不按月重置）  ────────┘              │
                                                          ▼
                              AI / 按量能力调用 → entitlement 预扣积分
                                                          │
                               ┌── 成功 → 结算确认 + 写流水
                               └── 失败/超时 → 全额退回 + 写流水
                                                          ▼
                             余额不足 → 降级为「仅查看 / 手动评分」，引导补充包或包月
```

**核心原则**

1. **积分即通行证**：是否包月不直接决定「能否用 AI」，**有余额即可用**；包月的价值是每月稳定发放积分 + 更多孩子/成员 + 导出与优先队列。免费体验用户与仅买补充包的用户也能使用 AI。
2. **额度归属家庭**：一个家庭一个消费积分账户，多孩子共享；owner 独占购买与消费管理权限。
3. **服务端唯一裁决**：所有高成本云函数入口先 `entitlement.reserve()`，客户端余额只用于展示。
4. **不得形成资金属性**：消费积分不可提现、不可转让、不可反向兑人民币、不可兑换成长积分、不可跨家庭转赠。

### 4.5 积分账本与扣减机制

**表设计（MySQL）**

| 表 | 关键字段 | 约束 |
| --- | --- | --- |
| `credit_accounts` | `family_id`(唯一), `balance`, `frozen`, `version` | 一个家庭一行；余额非负 |
| `credit_ledger` | `id`, `family_id`, `direction`(credit/debit/refund/expire), `amount`, `balance_after`, `biz_type`, `biz_id`, `idempotency_key`(唯一), `platform`, `expires_at`, `created_at` | 只追加不修改；`(family_id, created_at)` 索引 |
| `subscriptions` | `family_id`, `plan`, `status`, `period_start/end`, `platform`, `original_transaction_id` | 订阅状态机 |
| `orders` | `order_no`(唯一), `family_id`, `type`(subscription/topup), `sku`, `amount_fen`, `status`, `platform` | 幂等发货 |

**扣减流程（预扣 + 结算 + 幂等）**

1. `entitlement.reserve(familyId, action, requestId)`：读价目表版本 → CAS 扣减 `UPDATE credit_accounts SET balance = balance - ?, frozen = frozen + ?, version = version + 1 WHERE family_id = ? AND balance >= ? AND version = ?`，写冻结流水；`idempotency_key = familyId + action + requestId` 防重试重复扣。
2. 调用 CloudBase AI；成功 → 确认结算（减少 frozen、写 debit 流水、写 `ai_usage_logs`）；失败 / 超时 / 内容安全拦截 → **全额退回**（回补 balance、减少 frozen、写 refund 流水）。
3. 云函数异常退出时由定时任务扫描超时未结算的冻结记录并退回，避免「扣了分没出结果」。
4. 日终对账：`Σ credit_ledger.amount = credit_accounts.balance`，差额告警并冻结相关能力。
5. 所有扣减与退回在 MySQL 事务内完成；禁止用进程内存或客户端缓存记账。

### 4.6 支付与发货流程

| 环节 | 设计 |
| --- | --- |
| 包月下单 | `billing.createOrder(type=subscription)` 生成幂等订单号并签名；安卓/鸿蒙/Windows 会员订阅、iOS `wx.requestAppleSubscribeSign` |
| 补充包下单 | `billing.createOrder(type=topup)`；按平台核定的代币模式或道具模式拉起 `wx.requestVirtualPayment` |
| 发货 | 平台发货通知 → `billing.notify` **验签 + 幂等（订单号唯一索引）+ 事务**：写 `orders` 状态、`subscriptions` 或 `credit_ledger` 发放记录、更新 `credit_accounts` |
| 月度发放 | 定时触发器在订阅周期开始日发放当月积分；以 `period` + `family_id` 为幂等键，重跑不重复发放 |
| 双通道兜底 | 前端 `success` 仅刷新 UI；服务端定时 `query_order` 对「已支付未发货」补发；每日与平台账单对账 |
| 续费 / 退订 | 接收扣款预通知与结果 → 更新 `period_end` 并触发下一期发放；解约/退款/过期 → 订阅状态机 `grace → expired`，**不删除已购积分与业务数据** |
| 可观测 | 订单状态机、积分流水、`audit_logs`、失败告警、日终对账差异报表 |

### 4.7 有效期、结转与到期

| 来源 | 有效期 | 结转 | 订阅到期后 |
| --- | --- | --- | --- |
| 包月每月发放 | 当期有效，最长 90 天 | 未用完可结转至下一期，**结转上限为当期配额的 50%**，超出部分到期失效 | 未过期积分继续可用 |
| 积分补充包 | 自购买起 24 个月 | 不适用 | **继续可用，不因退订清零** |

### 4.9 防滥用与成本控制

| 层级 | 措施 |
| --- | --- |

| **Midjourney** | 订阅按档每月发放 Fast GPU hours，**用完可在 Manage Subscription 页「Buy more Fast hours」加购**；四档 $10–$120/月、年付约 8 折、无免费版；低档用尽即停，高档降级到 Relax 模式（官方文档，置信度高） | **与本方案同构的「订阅送额度 + 用尽加购」**；额度耗尽的分级降级策略；年付折扣 | 无免费版、纯生成工具；本产品有儿童与家庭租户，需要体验门槛与更温和的降级 |

| 小日常 | 极简打卡 + 免费 / 订阅 / 低价买断，长期不堆功能（第三方报道，置信度中） | 克制是壁垒，敢砍功能 | 无家庭租户复杂度 |

**战略含义**

1. **Midjourney 直接验证了本模型**：订阅是稳定收入，加购承接重度用户，降级策略避免「用尽即断」的挫败感。本方案据此设计「余额不足仍可查看、非 AI 功能不受影响」。
2. **GitHub Copilot 提醒保留成本弹性**：价目表与套餐须后台可配、带版本，不能把扣分规则写死在代码里。
3. 免费体验 + 一次性赠分保留获客入口，但**不做永久免费 AI**，避免可变成本失控。
4. 家长是付款人、孩子是使用者：付费入口只在 owner 端，孩子端不展示钱包。
5. 团队 / 学校版在家庭版留存达标前不启动。

## 6. 分阶段实施路线

**优先级原则**：项目骨架与配置冻结 > 可登录 > 数据隔离 > 积分账务 > 合规可上线 > 可收费 > 功能补齐。假设 1 前端 + 1 后端 + 0.5 测试/设计，人天含 20% 风险缓冲。

| 里程碑 | 目标 | 关键交付 | 验收标准 | 估算 |
| --- | --- | --- | --- | --- |
| **Gate 0 新建项目与配置冻结** | 独立仓库 + CloudBase 环境 + 不可回退配置定稿 | 新建仓库与 pnpm workspace；dev/staging/prod 三环境；MySQL/NoSQL/云存储/AI 资源开通；**冻结积分:人民币比例、补充包面额、AI 价目表 v1、有效期与结转规则**；启动小程序主体/类目/备案/虚拟支付开通；`origin/HEAD` 指回 `main` | 三环境可独立部署；沙箱验证兑换比例；价目表配置入库且带版本；取得支付开通受理号 | 3–5 天 + 审核等待 |
| **M1 身份与项目地基** | 按新架构重写地基 | `getWXContext().OPENID`、头像昵称能力、`members`/`child_profiles` 分离、access+refresh+`token_version`、参数化隔离层、统一入口、`@cloudbase/js-sdk` v3、TDesign 页面骨架 | 真机家长/孩子登录成功；伪造 openid 返回 401；停用后旧令牌 401；跨孩子读数据 404 | 10–14 人天 |
| **M2 租户隔离与权限** | 多家庭可用 | `family_id`/`child_id`、NoSQL 按租户、RBAC 三层校验、邀请码、审计日志、缓存键改造、定时任务按孩子分组、完整导出/删除 | 两家庭互不可见；规则不串；越权集成测试全绿；导出与 DDL 表清单一致 | 10–14 人天 |
| **M3 合规与上线准备（与 M2 并行）** | 通过审核 | 主体与类目、ICP 备案、隐私政策 + 儿童专门规则 + 监护人单独同意留痕、用户协议与《消费积分规则》、自动续费提示、内容安全、AI 显式/隐式标识、业务域名、订阅消息模板、日志脱敏、备份与监控 | 隐私合规自查逐项通过；提交审核前无 P0/P1 缺陷；积分性质与有效期文案走查通过 | 8–12 人天 |
| **M4 商业化：包月 + 积分账本** | 可收费、账务零差错 | `billing`/`entitlement`/`credit`/`notify` 云函数；`credit_accounts`/`credit_ledger`/`subscriptions`/`orders`；虚拟支付全终端接入（代币或核定模式）；月度发放、补充包、预扣结算、幂等退回、日终对账、成本熔断、账单与低余额提醒 | 沙箱跑通包月→发分→消耗→加购→续费→退订→退款/过期；**Σ流水 = 余额**；重复通知/断网重试不重复发分或扣分；iOS 与安卓分别验收 | 18–24 人天 |
| **M5 功能补齐与增长** | 提留存与 ARPU | 订阅消息触达、20 题测验 + 错题本、云端题库（只读）、字帖图片、跨孩子趋势、团队版预研 | 次周留存与付费转化达标；AI 成本 / 收入 ≤25% | 迭代排期 |

**总周期**：Gate 0 → M4 上线约 12–16 周（M2/M3 并行；支付审核等待不计入开发人天）。若仅 1 人按 1.8 倍拉长。

### 风险登记与应对

| 风险 | 概率 / 影响 | 应对 |
| --- | --- | --- |

| 未成年人合规（儿童数据、AI 标识） | 中 / 高 | M3 门禁；监护人单独同意留痕；导出/注销闭环；法务复核 |
| 包体积 / web-view 域名 | 中 / 中 | 字体云化 + 分包；业务域名提前备案 |
| 孩子端登录流失 | 中 / 中 | 家庭码 + PIN + 设备内快速切换三路并存，A/B 测试 |

### 成功指标

- **北极星**：周活跃家庭数（当周有至少 1 次作业提交或积分消耗的家庭）。
- L1：新家庭 7 日激活率 ≥40%；次周留存 ≥30%；体验→包月转化 ≥3%；包月续费率 ≥60%；补充包购买率 ≥8%；**积分账务差异率 = 0**；月 AI 成本 / 相关收入 ≤25%；退款率 ≤2%；审核一次通过；P0 线上缺陷为 0。

### 7.3 运营要点

- **额度运营**：低余额提醒、月度发放通知、过期前 7 天提醒、补充包组合推荐；严禁用「限时清零」制造焦虑（儿童产品合规敏感）。
- **成本看板**：日活家庭、积分发放/消耗/结余、单家庭 AI 成本、AI 成本 / 收入、补充包收入占比、异常突增 Top 10；预算告警联动降级开关。
- **账务日报**：`Σ流水 = 余额` 校验、订单与平台账单对账、退款与折算复核、冻结记录超时扫描；差异必须当日闭环。
- **客服与投诉**：「我的 → 我的额度」提供流水与订单查询；帮助与反馈、隐私行权入口；儿童相关投诉 24 小时内响应。
- **版本治理**：新仓库 `main` 为稳定分支；每次发版记录变更、价目表版本、合规自检与回滚方案；工作日志按项目规范记入 `.codebuddy/memory/`。
- **增长**：分享卡片是天然裂变点，但不得诱导分享、不得在孩子端出现付费引导。

## 附录 B：术语表

| 术语 | 含义 |
| --- | --- |
| 家庭（family） | 租户、计费主体、消费积分账户主体，数据隔离唯一边界 |
| 成员（member） | 真实微信身份，承载登录与角色 |

| **消费积分（credits，UI 建议称「AI 点」）** | 包月发放或补充包购买的站内额度，按家庭记账，仅用于消耗 AI 等按量能力，不可提现转让 |
| 代币模式 | 微信虚拟支付 `short_series_coin`，先充值再消费，需余额 / 流水 / 补偿，兑换比例发布后不可修改 |
| 道具模式 | 微信虚拟支付 `short_series_goods`，单次购买单次交付 |
| 预扣 / 结算 | AI 调用前冻结积分，成功确认扣减、失败全额退回的账务机制 |
| entitlement | 服务端权益裁决，所有高成本接口调用前必须校验并预扣 |
| CloudBase Layer | 云函数公共层，复用认证、数据库、隔离、积分与 AI 封装 |
